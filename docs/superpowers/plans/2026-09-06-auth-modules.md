# 模块拆分与持续登录实施计划

> 使用 superpowers:subagent-driven-development 完成独立前端任务，并在集成后审核。

**目标：** 按登录、笔记、待办组织代码，完善用户名密码登录，默认持续登录。

**架构：** React 业务目录配合 FastAPI APIRouter。服务端保留会话摘要，浏览器使用持久 HttpOnly Cookie；新会话不设强制登录期限（expires_at=0），启动与周期性的 /auth/me 刷新浏览器 Cookie 的 400 天有效期。认证请求串行并通过 Web Locks 协调标签页；业务响应不设置 Cookie，避免覆盖新登录凭证。旧限时 Bearer 会话只在有效时升级。主动退出撤销会话。

**约束：** 不接入第三方登录、邮箱、通知。不更改笔记待办功能或现有用户数据。仓库尚无初始提交，直接处理现有文件，不将用户全部未跟踪文件提交。

## 接口约定

- `/api/auth/register`、`login` 返回 `{id, username}`，通过 `qingjian_session` Cookie 设置会话，不返回 token。
- `/api/auth/me` 返回 `{id, username}`，未登录 401；禁止缓存认证响应。
- `/api/auth/logout` 幂等返回 204，撤销当前会话并清 Cookie。
- 所有非安全方法请求必须带 `X-Qingjian-Request: 1`，同源部署且不开放 CORS；存在 Origin 时验证可信来源。生产设置 COOKIE_SECURE=true，并按部署设置 TRUSTED_ORIGINS。
- 注册与登录各自按账号和 IP 限流，数据库固定窗口计数，429 带 Retry-After。错误响应包含 detail，可附 fields 字段错误映射。
- 前端请求使用 credentials: same-origin，业务接口 401 广播失效事件。认证恢复失败允许重试。工作台失效期间保持挂载但隐藏，原账号重登保留草稿，其他账号重挂载清空状态。
- 业务请求携带当前页面账号 `X-Qingjian-User`，后端与会话账号不一致时拒绝，避免多标签页切换 Cookie 后跨账号保存草稿。
