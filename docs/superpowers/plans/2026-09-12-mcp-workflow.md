# Codex 与青笺 MCP 工作流实施计划

用户已批准前述方案的第一至第三步。优先跑通，采用少量关键检查。

## 目标与范围

Codex 经本地 stdio MCP 服务调用青笺 HTTP 后端，实现跨对话查询、保存通知、创建及更新事务、关联笔记、设置提醒和维护个人资料。

不调用模型 API，不新增聊天界面；页面重构、后台推送、网站监控后续实施。身份来自独立登录会话，凭据不进入工具参数或结果。

## 文件与步骤

- [x] `backend/affairs/service.py`：提取现有事务业务，支持在调用者事务内执行，保持旧接口兼容。
- [x] `backend/agent/` 与 `0006_agent.py`：个人资料、原子幂等回执、读取及写入接口。写入使用请求 ID，冲突返回 409，失败不提交回执。
- [x] `integrations/qingjian_mcp/`：官方 SDK stdio 服务、HTTP 客户端、交互登录/撤销、配置生成。服务仅调用 HTTP，不访问数据库。
- [x] `skills/qingjian-workflow/SKILL.md`：查询优先、保留依据、未知时间留空、同一操作重试复用请求 ID、按结果汇报。
- [x] 验证迁移、账号隔离、重复请求和选课完整流程；验证真实 MCP 握手、工具发现及调用。
- [x] `docs/mcp.md`：安装、授权、Codex 配置、撤销、验收和已知边界。

## 关键约定

个人资料按账号保存，带版本。通知采用现有 information 记录；事务可引用 source_information_id，保留原通知而不是覆盖它。更新事务使用 expected_version；提醒和笔记关联只修改对应字段。MCP 凭据由用户在本地终端输入账号密码获得独立会话，凭据文件位于忽略的 data 目录，不存密码。HTTP 只允许回环地址或 HTTPS，禁用自动重定向。
