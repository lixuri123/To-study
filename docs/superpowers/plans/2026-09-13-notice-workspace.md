# 通知聚合、整理回执与采集恢复

用户已批准三个改进，沿用现有 React / FastAPI / MCP，不重复设计确认，不扩大测试。

1. 通知详情根据 source_information_id 聚合子事务、去重笔记、真实提醒及办理进度；事务可返回原通知。待确认时间单列。
2. GET /api/agent/receipts 按本人及记录筛选成功操作回执，分页；界面注明回执是历史操作，当前提醒以记录为准。
3. 在信息 JSON 中增加可选采集状态和有限历史。新增 MCP record_capture_attempt，记录 Agent 实际读取结果（成功/部分/失败、错误分类、缺失内容），支持原记录恢复，保留已采集原文，使用版本及幂等保护。不从后端请求任意 URL，不伪造自动采集。
4. 失败或部分采集可复制继续处理指令（包含记录 ID 和来源），用户交给 Agent；Agent 读取、有限重试后写回状态。验证码需用户处理。旧数据标为未核验，不推断完整。
5. 少量 API 检查覆盖账号隔离、版本冲突、重试去重及保留原文；前端构建与相关交互检查。已有桌面壳直接使用服务的新前端，无需重打安装包。

验收：打开报到通知可看到三项事务、关联笔记和9月15日提醒；展开回执查看操作；对测试通知记录一次失败再部分成功，确认历史与原文保留、复制重试指令可用。
