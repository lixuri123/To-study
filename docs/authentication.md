# 用户名密码登录

本版只提供用户名密码注册、登录与退出。第三方登录、邮箱绑定、邮件通知不在本轮范围内。

## 使用行为

- 注册时填写用户名、密码和确认密码，成功后直接进入工作台。用户名不区分大小写；密码保留原始空格。
- 无需勾选“记住我”。关闭页面、重启浏览器后通过持久 Cookie 恢复登录。
- 新服务端会话没有强制到期时间，直到主动退出或被撤销。旧版已过期的会话仍然无效。
- 浏览器 Cookie 有效期为 400 天，打开应用和周期性检查登录时自动刷新期限。浏览器清理数据、隐私模式退出或长时间不访问导致 Cookie 到期后，需要重新登录。
- 退出撤销当前浏览器会话并删除 Cookie，重复退出仍然成功；网络失败时提示重试，不谎报服务端已退出。
- 认证失败时保留当前页面内存中的笔记草稿，原账号重登恢复；换账号清除工作台状态。页面刷新后不恢复内存草稿。
- 初次检查登录遇到断网或服务端故障时提供重试，只有 401 才判定需要登录。

## 会话与请求

- Cookie：`qingjian_session`，`HttpOnly`、`SameSite=Lax`、`Path=/`，生产开启 `Secure`。
- 注册、登录和 `/api/auth/me` 返回 `{id, username}`，不返回明文 token。数据库只保存会话 SHA-256 摘要。
- 为避免旧业务响应覆盖新账号 Cookie，笔记、待办响应不设置 Cookie；续期集中在认证接口。
- 前端串行发送认证请求；支持 Web Locks 的浏览器同时协调同源标签页。没有 Web Locks 的浏览器只能保证单页内串行，多个标签页同时切换账号时可能需要重试登录。
- 业务请求携带当前页面的 `X-Qingjian-User`。若其他标签页切换了 Cookie 对应账号，后端拒绝旧页面请求，避免把旧账号草稿保存到新账号。该值只用于一致性检查，真实权限始终由服务端会话决定。
- 所有 API 响应禁止缓存。写请求必须带 `X-Qingjian-Request: 1`，并检查 Origin（如存在）；不开放跨域 CORS。此自定义请求头配合同源策略阻止跨站表单与脚本伪造写请求。
- 有效旧 Bearer 会话可经认证升级为持续会话，已过期旧会话不能升级。前端切换到 Cookie 后清除旧 `sessionStorage` 凭证，原有用户可能需要重新登录一次，数据不受影响。

## 限流

登录与注册分别按规范化账号和连接 IP 限流：每 5 分钟账号最多 5 次，IP 最多 30 次，包含成功与失败请求。返回 429 时附 `Retry-After` 秒数。

计数保存在数据库并使用原子更新，多个服务进程和服务重启不会重置窗口。过期记录会在后续认证请求时清理。用户名不存在与密码错误使用相同响应，并都执行密码哈希校验。

## 部署

| 环境变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | 默认项目 `data/app.db`；可配置 PostgreSQL 连接串 |
| `COOKIE_SECURE` | 本地 HTTP 默认为 `false`；生产 HTTPS 必须设为 `true` |
| `TRUSTED_ORIGINS` | 可选，逗号分隔完整来源，如 `https://notes.example.com`；未设置时只接受请求自身来源 |

推荐前端与 API 同源发布。反向代理部署需设置公开的可信来源，避免代理内部地址导致校验失败。限流读取服务端连接的客户端 IP；如经代理转发，须在 Uvicorn 中只信任受控代理的转发头，不能任意信任互联网请求的 `X-Forwarded-For`。

本地 Vite 开发代理使用 `changeOrigin: false` 保留浏览器访问的 Host，使其与 Origin 一致。不要将 `/api` 代理改回字符串简写：Vite 会默认开启 `changeOrigin`，把 Host 改为后端地址，导致注册、登录等写请求被来源校验拒绝。

执行 `uv run python main.py` 会自动迁移。若直接启动 Uvicorn，先执行 `uv run alembic upgrade head`。新增 `0002` 迁移只添加认证限流表，不重置业务数据；模型聚合文件保留 Alembic 注册和旧导入兼容。

## 验证

- 后端：根目录 `uv run pytest -q`。
- 前端：`frontend` 中 `npm test`、`npm run build`。
- Windows 系统临时目录权限异常时，为 pytest 指定项目内未使用的 `--basetemp=data/test-<run>`（pytest 会清理该测试专用目录）。

当前自动化后端测试使用 SQLite；PostgreSQL 限流使用同样的原子 upsert 语义，生产部署前仍应在目标 PostgreSQL 实例验证迁移与连接配置。
