# 青笺0.3.0验收

## 本轮行为

- 保留来源链接、发布时间、关键内容；不扩展网页、图片或PDF归档，已有原文保留。
- 同账号同一规范化链接复用信息记录，数据库唯一键防并发重复。链接参数仅移除已知追踪参数；无法识别短链接与长链接指向同一文章时仍需Agent搜索复用。历史重复记录不强制合并。
- 通知的标题、关键内容和时间变化保存最近20次对比。关联事务提示重新核对，点击“已核对本次变化”清除提示；个人提醒不自动覆盖。
- 详情可新增待确认问题、填写答案；时间不明仍单独显示。
- 提醒区可标记“我已知晓”，以及一小时后再提醒；可选择每小时或每天重复，最多3次。电脑未运行时错过的重复时段不会集中补发。送达不代表知晓，完成或取消停止投递。
- Windows0.3.0安装后，点击通知可打开对应事务；需要应用仍运行且登录。编辑尚未保存时不强制跳转，需保存后自行查看。
- Agent回执可多选、预览并确认撤销。后续手动修改或其他记录引用导致冲突时，整组不变。升级前回执没有快照，不能撤销。已发出的系统通知无法收回。

## 备份与恢复

事务页顶部“数据备份与恢复”可导出本人笔记、待办、通知事务、课表及个人资料，预览导入后确认新增恢复。相同文件不重复恢复、相同链接通知复用、不会覆盖当前数据。恢复的提醒标为已知晓，需手动重新安排。备份文件包含个人内容，请妥善保管。

个人导入不恢复账号会话、投递记录、旧回执或撤销历史。完整服务器灾备可运行：

```powershell
.venv/Scripts/python.exe scripts/database_backup.py data/app.db backups/app-20260914.db
```

该脚本执行SQLite在线一致性备份和integrity_check，目标必须是新文件。恢复服务器时先停止服务，保留原数据库及其WAL/SHM文件，用DATABASE_URL指向验证通过的备份再启动。PostgreSQL部署请使用数据库原生备份恢复，不使用SQLite脚本。

## 官网监控

已建立学校主站与学生处通知公告两条监控记录，每天09:00、18:00北京时间由本对话的Codex定时任务检查，结果存入青笺。暂停单一来源可在青笺记录内操作；整体任务在Codex自动化中暂停。

首轮主站HTTP412，学生处列表可读取但工具可能返回缓存，因此分别标为失败、部分完成；没有宣称全站监控正常。初次可靠读取建立基线，不把旧通知全数导入。仅对适用研究生的新通知、重要变化、新出现阻塞或需要用户行动通知；相同失败不反复打扰。

云端部署的是青笺后端，本版监控调度仍在Codex，未部署独立云端采集器。运行依赖Codex定时任务、可用网页工具及可访问的青笺MCP。部署地址变更后须在本机重新授权MCP到新服务地址。

## 建议验收

1. 刷新页面，打开现有报到事务，增加一个待确认项并填写答案。
2. 用测试通知验证相同链接复用、关键内容变化和关联事务提示。
3. 在测试事务设置两分钟后的提醒，安装0.3.0后点击系统通知，确认能进入事务；测试知晓与稍后提醒。
4. 用测试数据预览撤销；手动修改后应拒绝撤销，不能覆盖修改。
5. 导出备份，用测试账号预览恢复，确认关联笔记保留、重复导入不新增。
6. 查看官网监控状态，下一次计划检查为当日18:00（首次配置时间为9月14日10点后）。
